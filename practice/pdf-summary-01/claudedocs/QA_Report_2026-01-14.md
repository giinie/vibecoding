## 발견된 이슈 목록

### 1. Critical Issues (치명적 문제)

#### Issue #1: File Naming Inconsistency
- **심각도**: 🔴 CRITICAL
- **파일**: 프로젝트 루트
- **문제**: 메인 HTML 파일이 `index_pdf.html`로 명명되어 있으나, 서버 설정은 `index.html`을 기대함
- **영향**: Vercel 배포 실패 또는 로컬 서버 동작 불가
- **수정**: 파일명을 `index.html`로 변경 필요

```bash
mv index_pdf.html index.html
```

---

### 2. High Priority Issues (높은 우선순위)

#### Issue #2: Markdown to HTML Conversion Bugs
- **심각도**: 🔴 HIGH  
- **파일**: `index_pdf.html`, Lines 571-597
- **문제**: 
  1. 정규식 오류: `^\- (.*$)` → `^- (.*$)` (불필요한 백슬래시)
  2. 각 `<li>`를 개별 `<ul>`로 감싸 중첩된 태그 생성
  3. 정렬 목록 (`<ol>`) 지원 안 됨
- **영향**: 잘못된 HTML 구조, 렌더링 깨짐, 접근성 위반

#### Issue #3: XSS Vulnerability Window
- **심각도**: 🟡 MEDIUM-HIGH
- **파일**: `index_pdf.html`, Lines 599-617
- **문제**: `markdownToHtml()`이 안전하지 않은 HTML 생성 후 DOMPurify로 사후 정리
- **권장**: DOMPurify로 먼저 텍스트 정리 후 HTML 변환

#### Issue #4: Progress Bar Race Condition  
- **심각도**: 🟡 MEDIUM
- **파일**: `index_pdf.html`, Lines 639-650
- **문제**: `showProgress()` 호출 시마다 새 스피너 요소 생성, DOM 오염
- **수정**: 기존 스피너 제거 후 새로 추가

#### Issue #5: Memory Leak in PDF Processing
- **심각도**: 🟡 MEDIUM
- **파일**: `index_pdf.html`, Lines 520-540
- **문제**: PDF.js 문서 객체가 정리되지 않아 반복 업로드 시 메모리 누적
- **수정**: `finally` 블록에서 `pdf.cleanup()` 호출

#### Issue #6: Missing Input Size Validation
- **심각도**: 🟡 MEDIUM
- **파일**: `api/summarize.js`, `server.js`
- **문제**: 입력 텍스트 최대 크기 검증 없음, DoS 공격 가능
- **수정**: 500KB 제한 추가

---

### 3. Medium Priority Issues (중간 우선순위)

#### Issue #7: Missing Accessibility Features
- **심각도**: 🟡 MEDIUM
- **문제**: WCAG 2.1 미준수
  - ARIA 속성 누락 (role, aria-label, aria-live)
  - 키보드 탐색 미지원 (tabindex, Enter/Space 핸들러)
  - 스크린 리더 지원 부족
  - 포커스 관리 부족

#### Issue #8: No Duplicate Upload Prevention
- **심각도**: 🟡 MEDIUM
- **문제**: 처리 중 중복 업로드 방지 안 됨
- **수정**: `isProcessing` 플래그로 상태 관리

#### Issue #9: Inefficient Text Concatenation
- **심각도**: 🟢 LOW-MEDIUM
- **문제**: 반복문에서 `+=` 연산자로 O(n²) 성능
- **수정**: 배열 `push()` + `join()` 사용

#### Issue #10: Missing Error Message Display
- **심각도**: 🟡 MEDIUM
- **문제**: 일부 에러 경로에서 사용자에게 메시지 미표시
- **수정**: 모든 catch 블록에서 `showMessage()` 호출 확인

#### Issue #11: Hard-coded User Messages
- **심각도**: 🟢 LOW
- **문제**: 메시지가 코드 곳곳에 하드코딩됨
- **수정**: CONFIG 객체로 중앙화

#### Issue #12: No Progress Update Batching  
- **심각도**: 🟢 LOW
- **문제**: 페이지마다 진행률 업데이트로 과도한 DOM 리플로우
- **수정**: 5페이지마다 업데이트

#### Issue #13: Missing Copy Button Loading State
- **심각도**: 🟢 LOW
- **문제**: 복사 중 버튼 재클릭 가능
- **수정**: `disabled` 속성으로 비활성화
